# LSP и поддержка агента

Статус на 2026-11-24. Короткий вывод: **`ink lsp` — для редактора и человека;
до модели агента он не доходит**. Это проверено, а не предположено.

## Что проверено

1. `ink lsp` поднимается и отвечает: capabilities включают diagnostics, hover,
   definition, references, rename, code actions, completion, symbols,
   signature help, formatting.
2. `ink new` пишет `opencode.json`; если `ink` нет в `PATH`, подставляется
   абсолютный путь бинаря.
3. Агенту в `opencode run` диагностика **не приходит**. Два прогона:
   - «прочитай main.ink и назови диагностики» → агент ответил, что канала нет,
     и угадывал по тексту;
   - после `edit` с заведомой ошибкой — тоже без диагностик.
   В логе `~/.local/share/opencode/log/opencode.log` нет запуска `ink lsp`
   для этой сессии: в headless-режиме сервер LSP не стартует.
4. Даже в TUI диагностика — это подсветка для человека; отдельного tool
   «diagnostics/hover» у модели в наборе нет.

Следствие: **для агента LSP сейчас не даёт ничего**, кроме форматирования на
сохранение. Реальный канал — `ink check --json`, который агент запускает сам.

## Критерии (что значит «10/10 для агента»)

| # | Критерий | Сейчас |
|---|---|---|
| 1 | Диагностики после открытия и после правки, с кодом и hint | ✅ в редакторе, ❌ до модели |
| 2 | Предупреждения видны, не ломают гейт | ✅ |
| 3 | Hover: тип переменной, подпись функции, выведенный Go-тип | ✅ (выведенный тип печатается в именах Ink: `i32`, `u8[]`, `str`) |
| 4 | Completion: локальные, верхний уровень, builtin, ключевые слова, поля и методы после `.` | ✅ (после `.` было 0, теперь поля и методы) |
| 5 | Signature help для Ink, Go и конструктора среза | ✅ |
| 6 | Definition, references, rename; rename не перепривязывает имя | ✅ |
| 7 | Quick fix для механических диагностик | ◐ 9 кодов: const, `=`, `fn`, import, `or fail`, nil, `make` → `T[](n)`, `for (cond)` |
| 8 | Форматирование на сохранение | ✅ |
| 9 | Задержка: диагностика после правки < 300 мс на файле 500 строк | ✅ на малом проекте (~0.1–0.2 с); на большом не мерили |
| 10 | Агент может вызвать диагностику, hover, definition, completion | ✅ `ink mcp` (8 tools), `ink new` пишет его в `opencode.json` |

Итог: **10/10** — LSP для редактора, MCP для агента. Проверено: агент в
`opencode run` вызвал `ink_diagnose` и получил настоящие диагностики с кодами
и hint; `ink_quickfix` вернул `i32[](3)` для `make[i32](3)`.

## Что доделано в этот заход

- Completion после `.` для значения: поля и методы типа, с detail.
- Hover показывает выведенный Go-тип в именах Ink (`i32`, `u8[]`, `str`) и не
  печатает `invalid type`.
- Quick fix `make[i32](3)` → `i32[](3)` и `for (cond)` → `for (; cond; )`.
- Тесты: completion после `.`, hover на selector, code action `make-removed`.

## Сделано: `ink mcp`

MCP-сервер на stdio поверх `ink lsp` (подпроцесс). Tools: `diagnose` (тот же
`ink check --json`), `hover`, `definition`, `references`, `complete`
(поля и методы после точки), `symbols`, `rename` (с защитой от перепривязки),
`quickfix` (`make` → `T[](n)`, `for (cond)` → `for (; cond; )`, импорты,
`const`). `ink new` пишет сервер в `opencode.json` с `codemode: false`, чтобы
tools были видны напрямую.

Проверка: `opencode run` в проекте с ошибкой вызвал `ink_diagnose` и получил
диагностики; `ink_quickfix` вернул `i32[](3)`.
