# Ink — убрать `make`

`make` есть только потому, что `var` не умеет задать **длину** и **ёмкость**
slice. Всё остальное `var` уже делает.

## Что умеет `var` сейчас

```ink
var xs = i32[] {};          // len 0, cap 0, не nil
var xs = i32[] { 1, 2 };    // len 2
var a = i32[3] {};          // массив, значимый тип
var m = map[str, i32] {};   // литерал
var u: User;                // нулевая структура
var p: *User = nil;         // nil-указатель
```

Чего не умеет:

| Нужно | Сегодня | После 12a |
|---|---|---|
| slice длины n | `make[i32](n)` | — |
| slice длины 0 с запасом | `make[i32](0, n)` | — |
| map, готовая к записи | `map[str, i32] {}` | `var m: map[K,V]` |
| аллокация под ареной | `new[T]()` / `make[T](n)` | без изменений |

Итого: `make` держится на двух формах — `n` и `n, cap`. Карта уходит под `var`
решением 12a и `make` ей не нужен; каналов в языке нет; `new` — отдельная
история про арену.

## Вариант A — тип и есть конструктор: `T[](n)`

```ink
var xs = i32[](3);        // len 3, cap 3, нули
var buf = u8[](0, 4096);  // len 0, cap 4096
```

`make` удаляется из языка целиком, `var` читается как инициализация:
объявление задаёт тип и длину. Внутри `arena` та же форма идёт через арену.

- **Слой:** синтаксис Ink (новое выражение «тип + аргументы» для slice-типа),
  плюс sema/gen.
- **Цена:** ~150 строк (парсер 40, sema 40, gen 20, диагностика 15, миграция
  18 мест в примерах, тестах и guide), плюс код `make-removed` с hint
  `i32[](n)` и LSP-код-экшен, который переписывает механически.
- **Риск:** `i32[] { 3 }` — литерал из одного элемента, `i32[](3)` — три нуля.
  Формы рядом и различаются одной скобкой. Для агента это ловушка: обе
  компилируются, смысл разный. Лечится только дисциплиной guide и тем, что
  литерал пишется с пробелом, а конструктор — без.

## Вариант B — `zeros[T](n)` вместо `make`

```ink
var xs = zeros[i32](3);
var buf = zeros[u8](0, 4096);
```

- **Слой:** компилятор Ink (переименование builtin, нового синтаксиса нет).
- **Цена:** ~40 строк: парсер и sema уже разбирают `name[T](args)` для `make`,
  меняется имя и диагностика.
- **Плюс:** не конфликтует с литералом, читается как «n нулей».
- **Минус:** слово осталось, просто другое; «шум в инициализации» никуда не
  ушёл, только стал короче и честнее.

## Вариант C — без длины при создании

```ink
var xs = i32[] {};
xs = append(xs, 0);  // n раз
```

- **Слой:** ничего, только правило.
- **Цена:** ноль строк в компиляторе.
- **Минус:** `make([]byte, n)` — это чтение из файла/сокета, `append` в цикле
  там не замена (лишние реаллокации и копии). Отказ.

## Вариант D — оставить `make` только для арены

- **Минус:** два способа в одном языке; `make` вне арены всё равно нужен.

## Вариант E — массив и срез

```ink
var buf = u8[4096] {}[:];
```

Работает уже сегодня, без изменений в компиляторе.

- **Минус:** только константная длина (размер массива), и это скрытая
  аллокация в куче; для `n` из рантайма не годится.

## Рекомендация

**A**, если цель — чтобы инициализация читалась без служебного слова:
`var buf = u8[](0, 4096)` — это ровно «буфер на 4096», и `make` исчезает из
языка, guide и диагностик.

**B**, если важнее не трогать парсер и не плодить похожие формы: тот же смысл,
но слово остаётся.

Разница в цене — примерно 110 строк парсера/sema/gen против нуля. Разница в
риске — одна неоднозначная пара `i32[]{3}` / `i32[](3)`.

## Что ещё можно отдать `var` (не сейчас)

- 12a: `var m: map[K,V]` выделяет map — на паузе по решению владельца.
- `new[T]()`: вне арены его заменяет `&T{}`; внутри арены нужен именно
  арена-аллокатор, поэтому `new` остаётся. Универсальная форма `*T()` читается
  хуже, чем есть.
- Массивы уже выражаются типом и литералом; `var` им ничего не должен.
