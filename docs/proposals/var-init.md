# Ink — убрать `make`

**Статус: сделано 2026-11-24.** Форма: `T[](n)`, `T[](n, cap: m)`,
`T[](cap: m)`, `T[](size: n)`. `make` удалён, в исходнике он даёт
`make-removed` с hint. `slices.Grow` отвергнут владельцем.

`make` есть только потому, что `var` не умеет задать **длину** и **ёмкость**
slice. Всё остальное `var` уже делает.

## Что умеет `var` сейчас

```ink
var xs = i32[] {};          // len 0, cap 0, не nil
var xs = i32[] { 1, 2 };    // len 2
var a = i32[3] {};          // массив, значимый тип
var m = map[str, i32] {};   // литерал
var u: User;                // нулевая структура
var p: *User = nil;         // nil-указатель
```

Чего не умеет:

| Нужно | Сегодня | После 12a |
|---|---|---|
| slice длины n | `make[i32](n)` | — |
| slice длины 0 с запасом | `make[i32](0, n)` | — |
| map, готовая к записи | `map[str, i32] {}` | `var m: map[K,V]` |
| аллокация под ареной | `new[T]()` / `make[T](n)` | без изменений |

Итого: `make` держится на двух формах — `n` и `n, cap`. Карта уходит под `var`
решением 12a и `make` ей не нужен; каналов в языке нет; `new` — отдельная
история про арену.

## Вариант A — тип и есть конструктор: `T[](n)`

```ink
var xs = i32[](3);   // len 3, нули
var buf = u8[](0, 4096);
```

Форма аргументов — отдельный вопрос, разобран ниже (A1–A5).

`make` удаляется из языка целиком, `var` читается как инициализация:
объявление задаёт тип и длину. Внутри `arena` та же форма идёт через арену.

- **Слой:** синтаксис Ink (новое выражение «тип + аргументы» для slice-типа),
  плюс sema/gen.
- **Цена:** ~150 строк (парсер 40, sema 40, gen 20, диагностика 15, миграция
  18 мест в примерах, тестах и guide), плюс код `make-removed` с hint
  `i32[](n)` и LSP-код-экшен, который переписывает механически.
- **Риск:** `i32[] { 3 }` — литерал из одного элемента, `i32[](3)` — три нуля.
  Формы рядом и различаются одной скобкой. Для агента это ловушка: обе
  компилируются, смысл разный. Лечится только дисциплиной guide и тем, что
  литерал пишется с пробелом, а конструктор — без.

## Вариант B — `zeros[T](n)` вместо `make`

```ink
var xs = zeros[i32](3);
var buf = zeros[u8](0, 4096);
```

- **Слой:** компилятор Ink (переименование builtin, нового синтаксиса нет).
- **Цена:** ~40 строк: парсер и sema уже разбирают `name[T](args)` для `make`,
  меняется имя и диагностика.
- **Плюс:** не конфликтует с литералом, читается как «n нулей».
- **Минус:** слово осталось, просто другое; «шум в инициализации» никуда не
  ушёл, только стал короче и честнее.

## Вариант C — без длины при создании

```ink
var xs = i32[] {};
xs = append(xs, 0);  // n раз
```

- **Слой:** ничего, только правило.
- **Цена:** ноль строк в компиляторе.
- **Минус:** `make([]byte, n)` — это чтение из файла/сокета, `append` в цикле
  там не замена (лишние реаллокации и копии). Отказ.

## Вариант D — оставить `make` только для арены

- **Минус:** два способа в одном языке; `make` вне арены всё равно нужен.

## Вариант E — массив и срез

```ink
var buf = u8[4096] {}[:];
```

Работает уже сегодня, без изменений в компиляторе.

- **Минус:** только константная длина (размер массива), и это скрытая
  аллокация в куче; для `n` из рантайма не годится.

## Форма аргументов: чем заменить `(0, 4096)`

`u8[](0, 4096)` читается плохо: два числа без подписей. Варианты, как это
записать иначе.

### A1. Одно число, ёмкость — отдельной функцией

**Отвергнуто:** `slices.Grow` — лишний Go-вызов вместо записи; выбор владельца —
именованные аргументы (см. «Решение владельца»).

```ink
var buf = u8[](4096);              // 4096 нулей
var out = slices.Grow(i32[] {}, n); // len 0, cap n
```

Два аргумента не нужны в обычном коде: во всём репозитории форм `(n, cap)`
ровно одна (`tests/cases/slices`). `slices.Grow` уже работает (проверено:
`len 0, cap 64`), называется по делу и не прячет ёмкость в позицию.

- **Слой:** синтаксис Ink (только `T[](n)`), `slices.Grow` — обычный вызов Go.
- **Цена:** без второго аргумента парсер и sema проще; guide учит одной форме.
- **Риск:** в арене `slices.Grow` выделит вне арены, но арене ёмкость и не
  нужна: её куски фиксированного размера.

### A2. Именованные аргументы

```ink
var buf = u8[](size: 0, cap: 4096);
var xs = u8[](size: 4096);
```

- **Слой:** синтаксис Ink (именованные аргументы вызова — новая возможность).
- **Цена:** ~80 строк плюс вопрос «почему мои функции не принимают именованные
  аргументы»; для конструктора это оверкилл.
- **Плюс:** читается с полуслова, масштабируется на будущие конструкторы.

### A3. Ключевое слово вместо скобок: `of`

```ink
var buf = u8[] of 4096;
var buf = u8[] of 4096 cap 8192;   // если ёмкость нужна
```

- **Слой:** синтаксис Ink, новое зарезервированное слово `of`.
- **Цена:** ~30 строк парсера, ноль изменений в sema/gen (та же конструкция).
- **Риск:** ключевое слово ради одного случая; `of` пригодится разве что
  будущим коллекциям. Читается по-английски хорошо, для агента — лишняя форма.

### A4. Ключевое слово вместо пустых скобок: `zeros`

```ink
var xs = zeros[u8](4096);
var buf = zeros[u8](0, 4096);
```

Это вариант B из основного раздела: слово стоит перед типом и называет
результат. Нового синтаксиса нет вообще, `(0, 4096)` остаётся только в редком
случае с ёмкостью.

### A5. Скобки в типе: `u8[len 4096]`

```ink
var buf = u8[len 4096] {};
```

- **Слой:** синтаксис Ink, ключевое слово внутри типа.
- **Минус:** длина не является частью типа slice, а `u8[4096]` уже массив.
  Две почти одинаковые записи с разным смыслом — та же ловушка, что у A.

## Решение владельца

Выбраны именованные аргументы: `T[](n, cap: m)`, `T[](cap: m)`. Опускается
`size`, а не `cap`: `T[](cap: m)` — пустой срез с запасом. Порядок не важен,
метку несёт имя; форматтер печатает позиционный размер и `cap:`.

**Ограничение:** тип элемента должен быть именуемым. `*Point[](n)` читается
как разыменование, поэтому для среза указателей нужен алиас:
`alias PointPtr = *Point;` и `PointPtr[](n)`. То же для среза срезов.

## Рекомендация (архив, заменена решением владельца)

**A1**, если цель — чтобы инициализация читалась без служебного слова и без
пары чисел: `var buf = u8[](4096)` — это ровно «буфер на 4096», ёмкость живёт
в `slices.Grow`, и `make` исчезает из языка, guide и диагностик.

**A4 (`zeros`)**, если хочется, чтобы слово называло операцию: новый синтаксис
не нужен, но слово остаётся.

**A3 (`of`)** — если скобки раздражают сильнее, чем лишнее ключевое слово.

**A2** — только если именованные аргументы нужны и самим Ink-функциям, иначе
это синтаксис ради одного конструктора.

Цена A1 — около 110 строк парсера/sema/gen плюс миграция 18 мест; цена B — 40
строк переименования. Цена остальных форм — между ними.

## Что ещё можно отдать `var` (не сейчас)

- 12a: `var m: map[K,V]` выделяет map — на паузе по решению владельца.
- `new[T]()`: вне арены его заменяет `&T{}`; внутри арены нужен именно
  арена-аллокатор, поэтому `new` остаётся. Универсальная форма `*T()` читается
  хуже, чем есть.
- Массивы уже выражаются типом и литералом; `var` им ничего не должен.
