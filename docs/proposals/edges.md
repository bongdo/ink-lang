# Ink — решения по открытым краям

Ответ на `docs/product/EDGES.md`, раздел **Open**. В таблице 12 строк: номера
`1, 3…13`, строки `2` нет.

Каждый вариант помечен слоем:

- **синтаксис Ink** — меняется исходник или то, что язык принимает; нужны
  парсер, `SPEC.md`, `ink guide`, форматтер, примеры.
- **компилятор Ink** — parse/sema/gen/driver/LSP; `.ink` не меняется.
- **генерённый Go** — меняется `zz_ink.go` или runtime; `.ink` не меняется,
  но меняется поведение бинаря.

«Цена» — строки кода плюс тесты, без документации.

## 1. `missing-return` не проверяется внутри литерала

`resolveFuncLit` (`internal/sema/expr.go:845`) резолвит параметры и тело, но
финальную проверку `terminatesBlock` делает только `checkFunction`
(`internal/sema/check.go:179`). `gen/decl.go:207` подставляет
`panic("unreachable")`, поэтому Go молчит, а падает программа.

| Вариант | Слой | Цена |
|---|---|---|
| 1a. В `resolveFuncLit` после `checkBlock(lit.Body)`: `len(results) > 0 && lit.Arrow == nil && !terminatesBlock(lit.Body)` → `missing return in function literal returning T`. Код `missing-return` подхватится существующим `Classify`. | компилятор Ink | ~15 |
| 1b. В `gen/decl.go` вместо `panic("unreachable")` — `panic("ink: missing return at file:line")`. Падение остаётся, но сообщение указывает на литерал. | генерённый Go | ~5 |
| 1c. Не эмитить panic и отдать ошибку Go — позиция будет в `zz_ink.go`, а не в `.ink`; противоречит «диагностика в исходнике». | генерённый Go | отказ |
| 1d. Запретить fallthrough в литерале грамматикой — это тот же анализ потока, только раньше и грубее. | синтаксис Ink | отказ |

Берём **1a**; **1b** — как страховка до него.

## 4. Цикл инициализации через вызов функции

`findVarCycle` (`internal/sema/resolve.go:680`) ходит только по
инициализаторам и не заходит в тела свободных функций, поэтому `--fast`
молчит. Полный check ловит это через Go (`initialization cycle for a`).

| Вариант | Слой | Цена |
|---|---|---|
| 4a. В граф зависимостей добавить рёбра «глобал → функция → глобалы, которые она читает», транзитивно, с защитой от рекурсии; в сообщении путь `a -> f -> b -> g -> a`. | компилятор Ink | ~50 |
| 4b. Правило в `Classify`: `initialization cycle` → код `init-cycle`, hint «разорви цикл, инициализируй в main или в функции». Работает только в полном check, но hint появляется. | компилятор Ink | ~2 |
| 4c. Отдельный проход циклов в `--fast` поверх уже разобранного AST — то же, что 4a, другой точкой входа. | компилятор Ink | ~50 |
| 4d. Принять: полный check обязателен в цикле, guide это уже говорит. | — | 0 |

Берём **4b** сразу, **4a** — если `--fast` должен быть самодостаточным.

## 5. Проверка конформанса молча пропускает подписи

`typeKey` (`internal/sema/iface.go:40`) и `goKey` (`:333`) возвращают `false` на
массивах, генериках, вариадиках; `methodSet` — на генерик-типах. `checkAssign`
при `unknown` просто выходит.

| Вариант | Слой | Цена |
|---|---|---|
| 5a. Закрыть дыры по одной: `ArrayType` → `[N]T`, инстанцированный генерик → `pkg.Stack[int]`, флаг `variadic` в `sign`, multi-result уже есть. Табличный тест на каждый случай. | компилятор Ink | ~120 |
| 5b. Сравнивать `types.Type` через `go/types` вместо строк — точно, но требует typecheck внутри sema; для `--fast` это циклическая зависимость. | компилятор Ink | отказ |
| 5c. При `unknown` выпускать warning `conformance-unchecked`: тишина становится видимой машине и человеку. | компилятор Ink | ~10 |
| 5d. Генерировать `var _ Writer = (*Buf)(nil)` на каждом месте присваивания — Go и так проверяет это место, выигрыша нет. | генерённый Go | 0 |

Берём **5c** как честный минимум, **5a** — когда дойдут руки до генериков.

| 6d. Добавить Go-символы по `go/types` object identity — отдельная задача, не край. | компилятор Ink (LSP) | ~200 |

| 10b. Отдавать сигнатуру с type params и строку «результат выводит Go; напиши type args, чтобы увидеть». Честно, без инфраструктуры. | компилятор Ink (LSP) | ~10 |
| 10c. Требовать явные type args на Go-генериках — в духе «один канонический способ», но воюет с выводом Go и добавляет шум. | синтаксис Ink | ~30 |

## 12. Запись в nil map паникует при чистом check

`nil` — валидное значение map, поэтому проверка молчит до записи.

| Вариант | Слой | Цена |
|---|---|---|
| 12a. `var m: map[K,V]` без инициализатора генерируется как `make(map[K]V)`; явный `= nil` остаётся nil. Ноль-значение map становится рабочим, как у slice. Меняет наблюдаемое `m == nil`. | генерённый Go | ~10 |
| 12b. Warning `nil-map-write`: map объявлена без инициализатора и в этой же функции пишется по индексу. Ложных срабатываний нет, ложных пропусков — да (инициализация через helper). | компилятор Ink | ~40 |
| 12c. Разрешить `make(map[K, V])` — Go-форма, которую сейчас парсер отвергает; делает «сначала make» явным и проверяемым. | синтаксис Ink | ~30 |
| 12d. В gen обернуть запись проверкой и паниковать с позицией: `ink: write to nil map at file:line`. | генерённый Go | ~5 |
| 12e. Оставить как есть: паника Go называет причину. | — | 0 |

Берём **12b** (не меняет семантику) или **12a** (убирает класс ошибки целиком,
но меняет `m == nil`); **12c** — если нужен явный `make` для map.

## 13. `str(42)` — это `"*"`, а не `"42"`

`str` — конверсия в Go-стиле: число трактуется как code point. `check` чист,
`run` печатает `*`, ловит только `ink test` через `go vet`
(`conversion from int to string yields a string of one rune`).

| Вариант | Слой | Цена |
|---|---|---|
| 13a. Новый встроенный `itoa(n)` (и `ftoa(x)`), gen → `strconv.Itoa`/`FormatFloat`; `str` не меняется. | компилятор Ink | ~40 |
| 13b. Переопределить `str` для чисел на `strconv` — нельзя различить `rune` и число: оба `i32`, сломает `str('A')` молча. | компилятор Ink | отказ |
| 13c. Запретить `str` на числах, hint на `strconv.Itoa` / `fmt.Sprint` — ломает rune-конверсию, потому что `rune` = `int32`. | компилятор Ink | ~20 |
| 13d. Гонять `go vet` внутри `ink check` и маппить это сообщение в `str-number` с hint. Ловит на том гейте, которым агент реально пользуется. | компилятор Ink | ~10 |
| 13e. Формат-строки `f"id={n}"` — решает и это, и склейку, но это отдельное решение, а не фикс. | синтаксис Ink | ~200 |

Берём **13d** сразу (гейт), **13a** — как каноническую форму числа в строку.
