Ink: go, on err, or fail

Одно слово для параллельности, два — для ошибок, паника — это паника Go. Никаких скрытых контекстов и «цветных» функций.

Три формы одного слова

блок

go { ... };

Ветки — верхнеуровневые операторы. Блок ждёт их и отдаёт первую ошибку.

go {
    a = fetchA()
        or fail;
    b = fetchB()
        or fail;
};
цикл

go for ... limit N

Итерации параллельно, не больше N одновременно. Ждёт в конце.

go for (var y = i32(0); y < i32(H); y += 1) limit 4 {
    rows[y] = shadeRow(y, t);
};
задача

go f(args);

Отвязанная задача: запустил и пошёл. Живёт с программой, переживает обработчик запроса.

go saveUser(1, "hello");
// вернулись сразу

Время жизни

ФормаКто владеетЖдёт?

Правило: есть тело — ждём; нет тела — не ждём.

Проверки блока

можно

  • писать в свой слот: rows[y] = ...
  • читать захваченные значения
  • вкладывать go и go for

нельзя

  • писать в общий корень из двух веток
  • писать в global или self
  • break/continue наружу
  • for () внутри задачи

Два слова и паника

обработать

on err { ... }

На выражении — локально. В начале функции или блока — слушатель для go.

var u = loadUser(name)
    on err {
        http.Error(w, err.Error(), 500);
        return;
    };
вернуть

or fail

Утверждение: функция либо срабатывает, либо падает. С аргументом — оборачивает.

db.Exec(q)
    or fail("save user");

Слушатель в скоупе

fn handle(w: http.ResponseWriter, r: *http.Request) void {
    on err {
        log(err);
    };

    go saveUser(1, "hello");   // ошибка придёт в log
};

Слушатель — замыкание, захваченное задачей. Он может выполниться после выхода из функции: только лог, метрики, паника. fail/return внутри запрещены.

Пустой обработчик запрещён

Обработчик, который не выходит и не использует err, — это тихое проглатывание. После обработчика без выхода значение выражения — нулевое, как в Go.

Паника

panic(...) — это паника Go. on err её не ловит. go не заворачивает её в ошибку. Паника в любой горутине печатает стек и завершает процесс.

os.ReadFile("assets.bin")
    on err { panic(err); };
ФормаЧто делает
on err { ... }обработать здесь
or failвернуть ошибку
or fail("ctx")обернуть и вернуть
fail(err, "ctx")внутри обработчика: обернуть и вернуть
error("msg")создать ошибку
panic(...)Go-паника

Никаких _s_ctx, обёрток и Background-фолбэков. Bubble Tea Update с go удовлетворяет tea.Model без второй функции.

Три сценария

Веб-сервер

on err { log(err); };

fn handle(w: ResponseWriter, r: *Request) void {
    go saveUser(1, "hello");
    w.Write(bytes("ok"))
        on err {};
};

Фон переживает запрос; ошибки — в слушатель.

Игра: кадр

go for (var y = i32(0); y < i32(H); y += 1) limit 4 {
    rows[y] = shadeRow(y, t);
};

Арена даёт строки без GC; go for раздаёт их по ядрам.

Композитор

for () {
    poll();
    draw();
    if (quit) { break; };
};

Один событийный цикл. Ни go, ни каналов не нужно.
