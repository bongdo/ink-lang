# Contracts

## Что это

Внешние имена и наборы полей объявляются блоками внутри `type`. `wire` —
дефолтный вид; любой другой блок с именем в нижнем регистре — именованный вид
того же типа. Блок — allowlist: перечисленные поля уходят, остальные нет.

- `wire { ID: "id"; };` — дефолтный JSON-вид, компилируется в Go-теги.
- `admin { ID: "id"; };` — именованный вид, метод `u.admin()` возвращает
  `map[str, any]`; только кодирование.
- `wire Admin`, `check Admin`, блоки вне `type` и общий `contracts { }` не
  реализуются. `check`, `store`, `doc`, `policy` — обычные имена видов, не
  валидаторы и не схема БД.
- Именованный вид обязан использоваться; иначе `contract: named view ... is
  unused`.
- Поля в блоке обязаны быть экспортированы; ключи ограничены тем, что
  принимает `encoding/json`.
- Контракты на generic-структурах пока запрещены.

## Критерии приёмки

- `ink check --json` на типе с `wire` и `admin` возвращает `[]`.
- `json.Marshal(u)` не содержит не перечисленных в `wire` полей.
- `json.Marshal(u.admin())` содержит поля `admin` под заданными именами.
- Неиспользуемый `admin` даёт ошибку `contract`.
- Блок вне `type` даёт ошибку; пустой блок, несуществующее/неэкспортированное
  поле, дубль имени и ключ с запятой дают ошибку `contract`.
- `ink fmt` идемпотентен на типе с блоками.
