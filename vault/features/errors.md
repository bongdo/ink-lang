# Errors

## Что это

Ошибка — не значение, которое автор обязан таскать вручную. Fallible-вызов
сам говорит, что может упасть; `or` решает, что делать.

```ink
var raw = os.ReadFile(path)
    or fail;
var cfg = parse(raw)
    or fail("bad config");
```

- `or fail` возвращает ошибку вызывающему;
- `or fail("ctx")` оборачивает её контекстом;
- `or err { ... }` — локальная обработка, имя всегда `err`;
- внутри блока `fail(err, "ctx")` оборачивает и выходит;
- свежая ошибка: `fail(error("msg"))`;
- `or return` и `if err != nil { return err; }` отвергнуты.

## Критерии приёмки

- Слепой агент без документации чинит программу с `T or error` и `or return`
  по одним диагностикам.
- `fail("строка")` не проходит `ink check --fast`; `fail(error("msg"))` проходит.
- `or` в функции без `!` даёт ошибку с подсказкой.
- В `par` `or fail` и `fail(...)` добавляют ошибку воркера, а не паникуют.
